# القسم أ — الأساس الحاكم (يُبنى قبل أي وحدة)

## أ.١ المبادئ العشرة (تُنفَّذ كاختبارات آلية، لا كشعارات)

| # | المبدأ | كيف يُفرض تقنياً | نتيجة الخرق |
|---|---|---|---|
| ١ | كل قيد متوازن دائماً | `|Σمدين − Σدائن| ≤ 0.005` لكل عملة داخل القيد | رفض الحفظ |
| ٢ | المُرحّل لا يُعدَّل ولا يُحذف | منع UPDATE/DELETE على `journal_entry` حيث `posted=true` | خطأ قاعدة بيانات |

| ٤ | العملة الوظيفية محور التقارير | كل سطر: `currency + fxRate + amountBase` | تقرير null |

| ٦ | المخزون = مجموع حركاته | `product.qty == Σ stock_movement.qty` | فشل اختبار التكامل |
| ٧ | الأرصدة مشتقة | الرصيد من البنود؛ جدول الكاش يُعاد بناؤه | — |

## أ.٢ دورة حياة المستند (تنطبق على الفاتورة والسند والقيد والأمر والمسير)

| الحالة | قيد؟ | مخزون؟ | قابل للتعديل؟ | من ينقلها |
|---|---|---|---|---|
| **مسودة** | لا | لا | نعم | المنشئ |
| **معلّق** | لا | لا | نعم | المنشئ |
| **بانتظار اعتماد** | لا | لا | لا | المنشئ (فوق سقفه) |

## أ.٣ كيرنل القيد — الشيفرة المرجعية لكل شيء

```
postJournal(companyId, date, description, sourceType, sourceId, lines[])

الفحوص بالترتيب — أول فشل يوقف العملية كلها:
 ١. companyId موجود ونشط
 ٢. date داخل فترة مالية مفتوحة (period.status = OPEN)
 ٣. date > company.lockDate
 ٤. كل سطر: (debit > 0 XOR credit > 0) — لا صفر ولا سالب ولا الاثنان
 ٥. كل حسابId: موجود + نشط + ليس حساباً أبوياً (isGroup = false)
 ٦. currency في السطور المسموحة للمنشأة
 ٧. لكل عملة: |Σdebit − Σcredit| ≤ 0.005
 ٨. لا يوجد قيد سابق بنفس (sourceType, sourceId) ونفس الحالة posted
 ٩. إن كان هناك سطر ربح/خسارة عملة ⇒ يتوازن بالعملة الوظيفية أيضاً
١٠. كتابة القيد + البنود في معاملة واحدة (transaction)
١١. تحديث cache الأرصدة
١٢. تسجيل في audit_log
```

**قاعدة ذهبية:** كل دالة في التطبيق تنادي هذه الدالة. **ممنوع** على أي شاشة أو مستودع أن يبني قيداً بنفسه. هذا الخطأ موجود في `123` الحالي في ٤٠+ موضعاً، وهو مصدر كل خلل محاسبي.

**الكيانات:** `account` · `journal_entry` · `journal_line` · `period` · `cost_center` · `sequence` · `audit_log` · `attachment`.

# القسم ج — الآليات العابرة للوحدات

## ج.١ تكلفة المخزون (متوسط مرجّح) — أهم إصلاح بعد الكيرنل

```
استلام:  avg = (الرصيد × avg_قديم + الكمية × تكلفة_الاستلام) / (الرصيد + الكمية)
صرف:     cogs = الكمية × avg     ← والـ avg لا يتغير بالصرف
البيع:   مدين تكلفة المبيعات / دائن المخزون = cogs
```
**في التطبيق الحالي:** `unitCost = price × 0.72` ⇒ الربح الإجمالي غير صحيح في كل الشاشات.

## ج.٢ فروق العملة

```
سعر الفاتورة يُثبَّت (fxRateUsed) ولا يتغير.
عند السداد: فرق = (سعر السداد − سعر الفاتورة) × المبلغ ⇒ ربح/خسارة محققة.
نهاية الشهر: رصيد العملة الأجنبية × سعر الإقفال مقابل الدفتري ⇒ فرق غير محقق.
```

## ج.٣ توزيع القبض على الفواتير

```
الافتراضي: الأقدم أولاً (FIFO)، أو يدوي.
قبض ٥٠٠٠ من عميل عليه ٣٠٠٠ (متأخرة) + ٤٠٠٠
⇒ فاتورة أ مدفوعة، فاتورة ب جزئية ٢٠٠٠
⇒ حالة كل فاتورة وأعمار الديون تتحدث آلياً.
```

## ج.٤ المطابقة البنكية

```
١) استيراد الكشف → bank_line(date, ref, debit, credit)
٢) اقتراح آلي: مبلغ ±٥٪ وتاريخ ±٣ أيام ومرجع
٣) تأكيد/رفض المستخدم
٤) غير المطابق: حركة معلّقة أو قيد مفقود (رسوم/فوائد)
٥) الإقفال: رصيد الكشف = رصيد الدفتر + المعلّقات
```

## ج.٥ الإقفال الشهري (٧ خطوات)

١) لا مسودات · ٢) مطابقة الصناديق والبنوك · ٣) جرد وتسوية · ٤) إهلاك الشهر · ٥) استحقاقات · ٦) إعادة تقييم عملات · ٧) قفل الفترة.

## ج.٦ المزامنة بلا اتصال

```
كل كيان: id (UUID على الجوال) · updatedAt · version · deleted
الكتابة: DB + outbox + عرض فوري
العودة: إرسال بالترتيب؛ الخادم يطبّق ويرجع version
تعارض: حقول بسيطة ⇒ LWW لكل حقل؛ قيود مُرحّلة ⇒ رفض + إشعار
```

## ج.٧ الصلاحيات

مصفوفة `role × permission` من ٤٠ صلاحية. الخادم يفحص كل طلب. الواجهة تُخفي فقط (تحسين تجربة، لا أمان).

## ج.٨ الضرائب

```
على البند: base = (كمية × سعر) − خصم ؛ tax = base × rate
على الفاتورة: Σbase ⇒ Σtax ؛ سطر تقريب يضبط الفرق
الدفتر الضريبي: (base, tax, rate, date) لكل فاتورة
```

## ج.٩ ترقيم المستندات

`sequence(company, docType, year)` بقفل متفائل ⇒ `RV-2026-0001` بلا فجوات ولا تكرار بين جهازين.

# القسم ح — قائمة تحقق «١٠٠٪» (لا يُسلَّم النظام قبلها)

- [ ] كل قيد يُرحّل عبر الكيرنل الواحد فقط (لا قيد مبني في شاشة)
- [ ] لا جدول بلا `companyId`
- [ ] الفاتورة تحمل تكلفة حقيقية، والربح الإجمالي صحيح
- [ ] ميزان المراجعة متوازن بعد ١٠٠٠ حركة عشوائية
- [ ] لا مستند مُرحّل قابل للتعديل أو الحذف
- [ ] ١٤ نوع سند + ٩ أنواع فواتير + ٦ أنواع مشتريات تعمل بالقيود الصحيحة
- [ ] ١٢ تقريراً مالياً مطابقة للأستاذ
- [ ] تسجيل دخول وعزل منشآت وأدوار
- [ ] عمل بلا إنترنت ليوم كامل + مزامنة سليمة
- [ ] نسخ احتياطي مشفّر واستعادة كاملة
- [ ] طباعة A4 وحراري وتفقيط
- [ ] ٤٠ اختبار وحدة + ١٥ اختبار قبول ناجحة
- [ ] مراجعة محاسب مختص على ملف البلد الأول

**حين تُؤشَّر كل هذه، يصبح التطبيق محاسبياً مكتملاً — لا قبلها.**

## الخلاصة في خمسة أسطر

1. ما تملكه اليوم واجهة غنية فوق محرك غير مكتمل: **٦٧ ميزة منجزة من ٤٢٤** (١٦٤ جزئية · ١٩٣ ناقصة).
2. القطع الأربع التي تفتح الباقي: **قاعدة بيانات + كيرنل قيد + تكلفة مخزون + مصادقة**.
3. بعدها كل ميزة تصبح «وصلها بالمحرك» لا «ابنِها من الصفر».
4. المدة الواقعية لـ١٠٠٪: **٣٦ أسبوعاً** بمطوّر + مساعد ذكي.
5. لا تُسلِّم قبل اجتياز الـ١٥ اختباراً — عميل واحد يكتشف ربحاً خاطئاً يكفي لخسارة السوق.
